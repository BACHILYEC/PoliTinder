POLITINDER: ESTRUCTURA Y DATOS EN UN SOLO SCRIPT

01_ddl.sql contiene dos partes: CREATE DATABASE/CREATE TABLE (DDL) e INSERT (DML).
Se ejecuta UNA VEZ para crear una base nueva. No se concatena el antiguo ampliador
porque duplicaría los usuarios 21–30: la carga inicial ya contiene los 30 completos.

ORDEN: catálogos FACULTY, MAJOR, GENDER y SEXUALORIENTATION; USER; USERPHOTO;
LIKE; POLIMATCH; CHAT; MESSAGE; POLIDATE. Las FK requieren que existan primero
las filas referenciadas. Las inserciones usan listas explícitas de columnas.

USER: un INSERT por persona, con correo, hash PBKDF2, biografía y nombre ficticios.
bornDate usa DATE_SUB(DATE_SUB(CURDATE(),INTERVAL años YEAR),INTERVAL días DAY).
La resta adicional de días cambia el mes/día y evita cumpleaños iguales.
creationDate = NOW() menos (200 + id*4) días; updateDate = NOW() menos id*2 días.
La creación siempre precede a la actualización. Hay 30 valores diferentes de cada fecha.
La orientación inicial es «Prefiero no indicarlo»; la persona la cambia en Perfil.

USERPHOTO guarda 70 rutas existentes, no los bytes de las imágenes. Cinco perfiles
tienen cuatro fotos y los otros veinticinco dos. isProfilePhoto identifica la portada.

LIKE almacena emisor y receptor. POLIMATCH referencia dos likes opuestos.
CHAT referencia el match. MESSAGE usa DATE_SUB anidados para distribuir 24 mensajes
en días y minutos distintos. sender referencia al usuario que escribe.

POLIDATE incluye ocho valores explícitos de fecha/hora, distribuidos entre varios
meses de 2026 y 2027. Son datos de demostración, no evidencia de asistencia.
NOW() y CURDATE() se evalúan al ejecutar; las fechas explícitas no cambian.
SET time_zone='-05:00' hace coherente la carga con America/Guayaquil.

START TRANSACTION / COMMIT agrupan las inserciones. El DDL de MySQL no se revierte
con esa transacción. No se borra ni reemplaza automáticamente una base existente.

02_actualizar_base.sql es una migración separada y repetible para una base existente:
crea el catálogo, añade la columna si falta y su FK. PREPARE/EXECUTE permite elegir
ALTER TABLE solo cuando information_schema indica que falta la definición.
Conserva cuentas, claves, fotos, mensajes y fechas históricas. No recarga la demo.
